# 문제 해결

증상으로 찾으세요.

## 저장 파일을 열 수 없다 {#저장-파일을-열-수-없다}

상태 줄에 `열기 실패: <파일 이름>: <이유>`가 나옵니다. 이유는 영어로 나올 수 있습니다. 제품은 손상된 파일을 추측해서 고쳐 열지 않습니다. 문서는 열리지 않고 파일은 바뀌지 않습니다.

| 메시지 (종류) | 뜻 | 할 일 |
|---|---|---|
| 새 버전 파일 (`FutureVersion`) | 더 새 버전으로 만든 파일입니다 | 제품을 최신 버전으로 업데이트합니다 |
| 잘린 파일 (`Truncated`) | 파일이 끝까지 쓰이지 않았습니다 | 백업이나 이전 `.mpd`가 있으면 그것을 엽니다 |
| 검사합 불일치 (`ChecksumMismatch`) | 파일 내용이 저장할 때와 다릅니다. 손상되었습니다 | 백업이나 이전 `.mpd`가 있으면 그것을 엽니다 |
| 문서 정보 손상 (`ManifestInvalid`) | 레이어 목록 같은 문서 정보가 올바르지 않습니다 | 백업이나 이전 `.mpd`가 있으면 그것을 엽니다 |
| 타일 손상 (`TileInvalid`) | 그림 조각(타일)이 올바르지 않습니다 | 백업이나 이전 `.mpd`가 있으면 그것을 엽니다 |
| `.mpd`가 아님 (`NotMpd`) | 파일이 `.mpd`가 아닙니다 | 파일 종류를 확인합니다 |

## 펜이 감지되지 않는다 {#펜이-감지되지-않는다}

- 펜 입력은 Windows Ink(Unity 펜 이벤트)와 WinTab 두 경로가 있습니다. 기본(`Auto`)에서 Unity 2022.1 이상은 Windows Ink를 먼저 쓰고, Unity가 마우스로만 보고하면 WinTab이 채웁니다. Unity 2019.4와 2021.3은 WinTab을 씁니다.
- WinTab 드라이버(`wintab32.dll`)가 없으면 Windows Ink만 씁니다. 이때 필압이 나오지 않을 수 있습니다.
- 입력 경로는 `Auto`, Unity 이벤트, WinTab 중에서 고를 수 있습니다. 펜 진단 창과 펜 보정은 설정 창의 버튼으로 엽니다. 펜이 없으면 마우스로 칠해지고 필압은 1로 고정됩니다.

## 우클릭 메뉴가 없다

칠하기 메뉴는 재질 인스펙터 헤더의 `CONTEXT/Material` 메뉴에 있습니다. → [진입 방법](/getting-started/entry-points)

## VRAM 경고가 뜬다

VRAM은 열려 있는 문서의 크기와 레이어 수로 계산합니다. 계산한 값이 장치 메모리의 70%를 넘으면 경고 등급이고, 90%를 넘으면 위험 등급입니다. 쓰지 않는 문서는 잠재워(Sleep) VRAM을 비웁니다.

이 계산은 가정을 바탕으로 한 표에서 나옵니다. 실기 확인 전이라 이 문서에는 권장 수치를 쓰지 않습니다.

## 재생 모드로 들어가면 칠하기가 멈춘다

재생 모드로 들어가기 직전에 복구 기록을 먼저 쓰고 칠하기를 멈춥니다. 하던 획은 취소됩니다. 의도한 동작입니다. 재생을 끝내고 편집 모드로 돌아오면 칠하기가 다시 열립니다. 재생을 끝낼 때도 복구 기록을 먼저 씁니다. → [저장과 복구](/guides/save-recover)
