# トラブルシューティング

症状から探してください。

## 保存ファイルを開けない {#저장-파일을-열-수-없다}

ステータス行に `開けませんでした: <ファイル名>: <理由>` と表示されます。理由は英語で表示されることがあります。製品は壊れたファイルを推測して直して開くことはしません。文書は開かれず、ファイルも変更されません。

| メッセージ（種類） | 意味 | 対処 |
|---|---|---|
| 新しいバージョンのファイル（`FutureVersion`） | より新しいバージョンで作られたファイルです | 製品を最新版に更新します |
| 途中で切れたファイル（`Truncated`） | ファイルが最後まで書き込まれていません | バックアップや以前の `.mpd` があれば、それを開きます |
| チェックサムの不一致（`ChecksumMismatch`） | ファイルの内容が保存時と異なります。破損しています | バックアップや以前の `.mpd` があれば、それを開きます |
| 文書情報の破損（`ManifestInvalid`） | レイヤー一覧などの文書情報が正しくありません | バックアップや以前の `.mpd` があれば、それを開きます |
| タイルの破損（`TileInvalid`） | 絵の断片（タイル）が正しくありません | バックアップや以前の `.mpd` があれば、それを開きます |
| `.mpd` ではない（`NotMpd`） | ファイルが `.mpd` ではありません | ファイルの種類を確認します |

## ペンが検出されない {#펜이-감지되지-않는다}

- ペン入力には Windows Ink（Unity のペンイベント）と WinTab の 2 つの経路があります。既定（`Auto`）では、Unity 2022.1 以降は Windows Ink を先に使い、Unity がマウスとしてしか報告しない場合は WinTab が補います。Unity 2019.4 と 2021.3 は、WinTab のドライバーがあれば WinTab を先に使います。
- WinTab のドライバー（`wintab32.dll`）がなければ、Unity のペンイベント（2022.1 以降は Windows Ink）のみを使います。この場合、筆圧が出ないことがあります。
- 筆圧の取得元は `自動`、`Windows Ink`、`WinTab`、`マウス（筆圧なし）` から選べます。設定ウィンドウの `WinTab 診断を開く` ボタンでペンの診断ウィンドウを開き、ペンの補正（Calibrate）もそのウィンドウで行います。ペンがない場合はマウスで描かれ、筆圧は 1 に固定されます。

## 右クリックメニューがない

描画のメニューは、マテリアルのインスペクターのヘッダーにある `CONTEXT/Material` メニューにあります。→ [描画を始める入り口](/getting-started/entry-points)

## VRAM の警告が出る

VRAM は開いている文書のサイズとレイヤー数から計算します。計算値がデバイスメモリの 70% を超えると警告レベル、90% を超えると危険レベルになります。使っていない文書はスリープ（Sleep）させて VRAM を空けます。

この計算は仮定に基づく表から出ています。実機での確認がまだなので、この文書では推奨値を書いていません。

## 再生モードに入ると描画が止まる

再生モードに入る直前に、復元の記録を先に書き込んでから描画を止めます。描いていたストロークは取り消されます。これは意図した動作です。再生を終えて編集モードに戻ると、描画が再び開きます。再生を終えるときも、復元の記録を先に書き込みます。→ [保存と復元](/guides/save-recover)
